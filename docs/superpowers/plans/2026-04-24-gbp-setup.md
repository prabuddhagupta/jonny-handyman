# GBP Setup + Review-Pipeline Stub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Align John's Philadelphia handyman site with the new Google Business Profile name "John's Handyman House Repair", stub a dormant review-request pipeline that activates once GBP verifies, and ship an operational playbook John executes on business.google.com.

**Architecture:** Three independent pieces, one PR: (1) brand rename — pure string changes via `site.config.ts` + two hardcoded strings in `icons.tsx` + README header; (2) review-pipeline stub — a new `googlePlaceId` config slot, a `reviewLink()` helper that returns `null` until the slot is filled, a conditional footer link, and a conditional form-success nudge, all dormant until the Place ID is pasted in post-verification; (3) `docs/gbp-setup.md` — standalone operational playbook.

**Tech Stack:** Next.js 16 App Router, Tailwind v4, TypeScript, React 19.

**No test framework exists in this repo.** `package.json` has no test script, no vitest/jest/playwright. Verification is done via `pnpm build` (catches type and import errors), `pnpm lint`, and a dev-server visual check. This is a pragmatic choice for a content-heavy marketing site — not a rejection of TDD. Plan steps use `pnpm build` + manual toggle of `googlePlaceId` as the verification loop.

- [ ] **Step 2: Add `reviewLink()` helper**

At the end of the file, directly after `whatsappLink()`, add:

```ts
/** Helper — Google Business Profile review form link.
 *  Returns null until googlePlaceId is set (post-GBP-verification).
 *  Consumers should null-check and not render the CTA when null. */
export function reviewLink(): string | null {
  return site.googlePlaceId
    ? `https://search.google.com/local/writereview?placeid=${site.googlePlaceId}`
    : null;
}
```

Replace with:

```tsx
  if (state?.ok) {
    const review = reviewLink();
    return (
      <div className="p-8 rounded-xl border border-[var(--color-whatsapp)] bg-green-50">
        <CheckCircle2 className="size-8 text-[var(--color-whatsapp)]" />
        <h3 className="mt-3 text-xl font-semibold text-[var(--color-brand)]">
          Thanks — {site.ownerName} will be in touch.
        </h3>
        <p className="mt-2 text-[var(--color-muted)]">
          You&apos;ll usually hear back within a few hours. In a rush? Send a
          WhatsApp and skip the queue.
        </p>
        {review && (
          <p className="mt-4 pt-4 border-t border-[var(--color-whatsapp)]/30 text-sm text-[var(--color-muted)]">
            Already had {site.ownerName} out for a job?{" "}
            <a
              href={review}
              target="_blank"
              rel="noopener noreferrer"
              className="font-medium text-[var(--color-brand)] hover:underline"
            >
              Leave a Google review →
            </a>
          </p>
        )}
      </div>
    );
  }
```

Notes:
- The wording "Already had John out for a job?" is conditional by design — most form submitters are new leads, but returning customers sometimes re-submit; the phrasing applies naturally to them without confusing first-timers.
- Visual separator (`border-t`) distinguishes the review ask from the primary "we'll be in touch" message.
